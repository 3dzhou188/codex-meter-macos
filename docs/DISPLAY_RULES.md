# Codex Meter 显示规则

本文档是额度圆环和 Agent 状态灯的统一检视基准。修改任何显示逻辑时，应同步检查本文档、实现代码、自动化测试和 GitHub 示意图。

## 额度数据识别

- 5 小时额度只识别 `windowMinutes = 300` 的窗口。
- 7 天额度只识别 `windowMinutes = 10080` 的窗口。
- 剩余比例计算为 `100 - usedPercent`，最终限制在 `0...100` 之间。
- Codex 只返回 7 天窗口、没有 5 小时窗口时，5 小时额度视为「暂无限制」。
- 无法识别到某个窗口且不符合「暂无限制」条件时，该圆环显示无数据状态。

## 额度颜色

颜色根据「剩余比例」判断，不是已用比例。边界值按下表归类。

| 剩余比例 | 级别 | 显示颜色 | AppKit RGB | 近似 Hex |
| --- | --- | --- | --- | --- |
| `75%...100%` | `high` | 深绿 | `(0.09, 0.53, 0.23)` | `#17873B` |
| `50%...74%` | `good` | 浅绿 | `(0.45, 0.75, 0.27)` | `#73BF45` |
| `30%...49%` | `medium` | 黄 | `(0.89, 0.70, 0.10)` | `#E3B31A` |
| `10%...29%` | `low` | 橙 | `(0.93, 0.49, 0.10)` | `#ED7D1A` |
| `0%...9%` | `critical` | 红 | `(0.85, 0.21, 0.21)` | `#D93636` |

边界检视点：`75%` 必须是深绿，`50%` 必须是浅绿，`30%` 必须是黄色，`10%` 必须是橙色，`9%` 必须是红色。

## 圆环绘制

- 每个额度圆环固定为 16 段。
- 第一段从 12 点方向开始，激活段按顺时针方向依次填充。
- 相邻段的起点间隔为 `22.5°`，每个可见弧段为 `14°`。
- 未激活段使用次要文字颜色并设为 `25%` 不透明度。
- 激活段数量按剩余比例向上取整：`ceil(clamp(percent, 0...100) / 100 * 16)`。
- `0%` 显示 0 个激活段；任何大于 `0%` 的剩余量至少显示 1 段。

16 段圆环的整数百分比映射：

| 剩余比例 | 激活段数 | 剩余比例 | 激活段数 |
| --- | ---: | --- | ---: |
| `0%` | 0 | `51%...56%` | 9 |
| `1%...6%` | 1 | `57%...62%` | 10 |
| `7%...12%` | 2 | `63%...68%` | 11 |
| `13%...18%` | 3 | `69%...75%` | 12 |
| `19%...25%` | 4 | `76%...81%` | 13 |
| `26%...31%` | 5 | `82%...87%` | 14 |
| `32%...37%` | 6 | `88%...93%` | 15 |
| `38%...43%` | 7 | `94%...100%` | 16 |
| `44%...50%` | 8 | | |

### 特殊状态

- 「暂无限制」：按 `100%` 处理，16 段全部点亮为深绿色，圆心显示 `∞`，菜单内进度条也保持深绿满格。
- 「无数据」：没有激活段，圆心显示 `--`。
- 圆心数字显示剩余的整数百分比，不显示 `%` 符号。

## Agent 状态灯

三盏灯从左到右固定为「红、黄、绿」。未点亮的灯显示为灰色。

Agent 灯颜色：

| 灯 | AppKit RGB | 近似 Hex |
| --- | --- | --- |
| 红 | `(0.85, 0.20, 0.18)` | `#D9332E` |
| 黄 | `(0.94, 0.68, 0.12)` | `#F0AD1F` |
| 绿 | `(0.12, 0.72, 0.30)` | `#1FB84D` |

### 灯语对照

| Agent 信号 | App 文字 | 灯语 | 含义 |
| --- | --- | --- | --- |
| `idle` | 空闲 | 绿灯常亮 | 当前没有检测到 Agent 活动。 |
| `thinking` | 思考中 | 绿灯强闪 | 已收到任务，正在推理。 |
| `working` | 工作中 | 绿灯柔和闪动 | 正在调用工具、读写文件或运行测试。 |
| `tool_done` | 步骤完成 | 绿灯柔和闪动 | 一个工具步骤已结束，任务仍可能继续。 |
| `done` | 已完成 | 绿灯常亮 | 任务已完成。 |
| `attention` | 需要查看 | 黄灯柔和闪动 | 需要用户查看、回复或继续操作。 |
| `permission_request` | 等待授权 | 红灯强闪 | 必须处理授权请求后才能继续。 |
| `blocked` | 阻塞/失败 | 红灯常亮 | 事件明确报告失败或工作无法继续。 |
| `stale` | 状态不可用 | 黄灯常亮 | Agent 状态数据确实无法读取。 |
| `paused` | 已暂停 | 三灯全灭 | Agent 状态监控已关闭。 |

### 闪动节奏

- App 每秒更新一次灯光动画。
- 强闪在 `100%` 和 `8%` 强度之间交替，暗相接近熄灭。
- 柔和闪动在 `100%` 和 `28%` 强度之间交替。
- 强闪和柔和闪动的切换频率相同，区别是暗相深度，不是速度。
- 常亮状态始终使用 `100%` 强度。

## Agent 状态判断

### 自动退出

- `done` 完成状态保留 30 秒，然后从活跃会话中移除。
- 其他会话超过 30 分钟没有新活动时，直接从活跃会话中移除并回到空闲。
- 过期会话不得转换为 `stale` 或显示黄灯。
- 本地状态缓存损坏时按可恢复缓存处理，回到空闲；真正的文件读取失败才显示 `stale` / 状态不可用。

### 失败与恢复

- 只有事件自身明确报告失败、错误、阻塞、非零退出码或 `success: false` 时，才进入 `blocked`。
- 工具读取到的普通数据中含有 `error`、`failure` 或 `success: false` 不得触发阻塞。
- `blocked` 可被后续的思考、工作、工具完成、任务完成、等待授权或暂停事件解除。
- `permission_request` 会保留，直到收到工具完成、任务完成、新的授权请求、阻塞或暂停事件。
- `attention` 会保留，直到用户继续产生新的思考、工具完成、任务完成或更高优先级状态。

### 多会话汇总

多个 Agent 会话并行时，状态栏只显示一个汇总灯语。普通会话的优先级从高到低为：

1. 阻塞/失败 `blocked`
2. 等待授权 `permission_request`
3. 需要查看 `attention`
4. 活动中：`thinking` / `working` / `tool_done`
5. 已完成 `done`
6. 空闲 `idle`

- `paused` 是监控开关关闭后的全局状态，不参与普通会话优先级比较。
- `stale` 是状态文件真正读取失败时的全局异常状态，不是会话超时后的状态。
- 如果存在任何正常的新会话状态，旧的异常或过期记录不得覆盖正常活动。
